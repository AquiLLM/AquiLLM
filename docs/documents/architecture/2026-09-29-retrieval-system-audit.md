# AquiLLM retrieval audit and research recommendations

**Audit date: 29 September 2026. Documentation reconciliation: 29 September 2026.**

Analyzed checkout `75efe98c918072649e690979ffdf7211b6d4c455`, working backward from answer generation to ingestion. Three research agents separately investigated search/ranking, ingestion/representation, and graph retrieval. Findings were reconciled against that audit baseline. The audit itself did not change application code, configuration, running services, or architecture documents. Its test counts and research comparisons below remain historical results, not freshly rerun results for the later stability release.

The main opportunity is to improve the evidence that survives the existing pipeline. AquiLLM already has hybrid retrieval, graph expansion, reranking, adaptive selection, source authorization, citation enforcement, and substantial evaluation infrastructure. The highest-confidence gaps are embedding-space compatibility, prefix truncation, weak lexical ranking, and incomplete conversational query resolution. More elaborate graph traversal should follow measured evidence of benefit.

This is a source audit and research assessment. It does not establish current deployment flags, database execution plans, corpus contamination, live latency, or improvements in answer accuracy. Code fallbacks, checked-in example settings, and historical operational notes are distinguished below.

## Reconciliation with the stability release

The [current retrieval-path reference](2026-09-28-knowledge-graph-and-retrieval-pipeline.md) describes development revision `9518c6d51b74d163d594de29ec3a8764a63f56c3`. That release adds durable document chunk publication, chat execution/tool ownership, atomic transcript/scope saves, accurate incomplete conversation indexes, coalesced recoverable memory work, and startup/readiness repairs. These improve delivery and recovery around retrieval; they do not implement or validate the ranking, embedding-identity, parser or answer-quality experiments proposed below. Development transcription is intentionally disabled for capacity and must not be treated as a service to restart.

Code citations in this audit remain pinned to its original revision so the historical observations and line references can be inspected. The architecture guide links the updated implementation. No live retrieval benchmark or new source-corpus quality assessment was performed for this documentation reconciliation.

## The system, back to front

| Stage | Behavior at the audit revision | Main constraint or opportunity |
|---|---|---|
| Answer and citations | Synthesis receives the selected evidence packet; old tool evidence is removed from the request copy. Citation checks enforce permitted identifiers and placement, with repair paths. | A valid citation does not establish that the passage supports the claim. Preserve the existing packet/citation alignment and measure entailment. |
| Evidence delivery | Legacy delivery uses public excerpts. Source mode can hydrate exact, revision-bound spans, account for remaining model context, and revalidate before delivery. | Public excerpts default to 1,500 characters; source mode is separately gated. |
| Final selection | Adaptive mode hydrates authorized candidates, obtains comparable primary-query scores, and selects relevance-first with a redundancy penalty under token, passage, and document caps. Incomplete scoring falls back for the whole pool. | The selector cannot recover evidence discarded earlier. Relative normalization is not an answerability score. |
| Query-list fusion | Up to three searches run concurrently and are combined using RRF. Adaptive selection can retain a union of up to 45 returned rows. | Three searches occur only when query preparation supplies three queries. The per-search return cap is 15. |
| Passage reranking | Baseline and authorized graph candidates share the reranker. Scored and rank-only adapters, score reuse, and windowed scoring already exist. | Legacy local adapters default to the first 900 characters of each passage. |
| Candidate retrieval | Authorized dense L2 search, whole-passage trigram search, and exact-term search run sequentially; candidates are concatenated and deduplicated. | This baseline union is not dense/lexical RRF. Exact hits are limited after document-ID/chunk ordering. |
| Graph expansion | Direct query-entity seeds and extended passage-derived seeds each run bounded projected PPR; identities map back to provenance-checked passages. | Graph rank is an intermediate discovery signal. Seed relevance, mapping, branch caps, and overhead all affect useful additions. |
| Index construction | Uploaded text becomes overlapping chunks and embeddings, with transactional replacement and graph rebuild scheduling. Graphs have document, collection, and canonical identities. | Document vector provenance is weaker than graph vector provenance; chunks are character slices. |
| Extraction | PDF text, structured-format parsers, OCR and figure extraction feed documents. arXiv has its own source/PDF route. | Scientific structure and original page/region coordinates are not consistently preserved in body text. |

The default direct path asks for 10 final passages but requests 15 candidates per query. With the source fallback candidate settings, each dense/trigram/exact branch has a limit of 17, or up to 51 rows before deduplication and graph additions; reranking returns at most 15. Three query lists can therefore contribute up to 45 distinct returned candidates. These are upper bounds, not observed counts. A manual tool request for top 10 has different intermediate limits. Raising the final context budget cannot recover passages eliminated at any earlier cutoff. [Direct limits](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/chat/services/rag_config.py#L32), [actual dispatch](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/chat/services/rag_pipeline.py#L162), [branch limits](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/documents/services/chunk_search_limits.py#L39).

## 1. Establish a trustworthy measurement baseline before rollout

There is already an 80-case frozen evidence-quality corpus, split 40 development / 40 held-out, covering ten scenarios including tail evidence, negation boundaries, four-passage support, follow-ups, second searches, stale sources, revocation, cancellation, and global limits. A live ASGI runner compares baseline, selection, preservation, and combined modes; it supports human claim/citation reviews and source/model/hardware snapshots. Reuse this infrastructure. [Quality runner](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/chat/evals/run_evidence_quality_eval.py#L44), [quality metrics](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/chat/evals/evidence_quality_eval.py#L238).

The smaller selection replay has nine synthetic regression cases and explicitly reports `unmeasured_real_corpus`. The 80 scenario fixtures also do not by themselves demonstrate representative collection quality. Add independently labeled real questions covering identifiers, semantic paraphrases, cross-paper comparisons, multi-hop support, numeric/table questions, conversational references, narrow permission scopes, and unanswerable questions. Freeze source revisions and hold out questions before tuning.

Measure evidence survival at acquisition, post-reranking, final selection, and the actual model request. Use support-span recall, complete supporting-set recall, nDCG, citation entailment/completeness, abstention quality, fallback rates, and cold/warm p50/p95 latency. Candidate count and a syntactically cited answer are insufficient. ALCE provides a citation-quality evaluation reference; ARES separates context relevance, faithfulness, and answer relevance and uses human annotations to calibrate automated judgments. These are methodological references, not a requirement to adopt either framework. [ALCE](https://aclanthology.org/2023.emnlp-main.398/), [ARES](https://arxiv.org/abs/2311.09476).

## 2. Enforce document embedding compatibility — highest correctness priority

Durable document chunks use a local embedding path that can fall back to Cohere. `TextChunk` has no required embedding-model signature, and dense retrieval does not filter by one. Matching full-text hashes can reuse old chunk boundaries and vectors without checking model, parser, or chunker identity. Padding/truncating vectors to the same dimensions cannot make unrelated embedding spaces compatible. These are verified paths; actual mixed-model data in the running index has not been established. [Provider fallback](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/aquillm/utils.py#L132), [duplicate reuse](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/documents/tasks/chunking.py#L112), [vector field](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/documents/models/chunks.py#L56), [dimension fitting](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/lib/embeddings/utils.py#L12).

Extend the strict, versioned embedding contract already used by the knowledge graph to document vectors. Record model/revision, dimensions, preprocessing/template, normalization, actual modality, and source/chunker identity. Bind responses to input indices and require compatible query/index signatures. During provider outages, use lexical retrieval or a separately compatible vector index rather than silently mixing spaces. Make duplicate reuse depend on this identity. [Existing strict seam](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/aquillm/utils.py#L214).

Validate formatting against the actual running model before changing it. Python defaults and example deployment settings name different Qwen models, and text and vision-language models have different input contracts. The Qwen text model documentation uses task instructions and normalized vectors. [Official Qwen embedding example](https://huggingface.co/Qwen/Qwen3-Embedding-4B).

First experiments: provider outage, model-revision changes with unchanged document text, shuffled response indices, and malformed dimensions. Require zero incompatible vectors published. Then compare retrieval quality with model-correct preprocessing. Cost: schema/versioning work and controlled re-embedding of existing data.

## 3. Evaluate the existing preservation path to remove evidence truncation

Active chunks default to 2,048 characters with 384-character overlap. Legacy local reranking sees a 900-character prefix; public tool excerpts default to 1,500 characters. Thus a qualification or answer near the end can be omitted from scoring, delivery, or both. This is a code-level coverage gap, not a measured error rate. [Chunk defaults](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/aquillm/apps.py#L89), [rerank prefix](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/documents/services/chunk_rerank_config.py#L125), [public excerpt](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/chat/consumers/utils.py#L31), [legacy hydration](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/chat/services/rag_selection_hydration.py#L93).

Windowed reranking and exact-source evidence already exist, including template-aware pair counting, source fingerprints, overlaps, deadlines, and request-context accounting. Run the existing four-arm evaluation to distinguish gains from selection, preservation, and their combination. Test support before character 900, between 900 and 1,500, and after 1,500; include negation, units, table headers, and multilingual text. Compare complete support delivered, windows per passage, scoring work, and p95. Max-over-window scoring also needs a long-passage bias check. [Window implementation](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/documents/services/chunk_rerank_windows.py#L168), [context allocation](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/chat/services/rag_context_budget.py#L117).

Do not enable every preservation switch together. Source delivery, windowed scoring, document capacity, follow-up continuity, and iterative acquisition are separately controlled and have validated dependencies. [Switch validation](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/chat/services/rag_preservation_config.py#L71).

## 4. Strengthen lexical retrieval and fallback ordering

Whole-passage trigram similarity supplies the main lexical ranking. Exact retrieval OR-matches salient terms and truncates after sorting by document UUID and chunk number. A broad term can occupy the exact allowance before later documents are considered. Dense-first concatenation also means reranker failure can favor dense results while suppressing useful lexical-only additions. [Lexical acquisition](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/documents/services/chunk_search_candidates.py#L219), [rerank fallback](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/documents/services/chunk_rerank_parse.py#L21).

Evaluate a PostgreSQL full-text branch with title/section weighting and relevance-ranked phrase/identifier coverage. Keep trigram for spelling variation and deliberate exact handling for scientific identifiers. PostgreSQL `ts_rank_cd` is an available baseline; it is not BM25. Inspect generated SQL and query plans before making index-performance claims. The current `similarity(...) > threshold` expression should be checked against the documented indexed trigram operators. [PostgreSQL ranking](https://www.postgresql.org/docs/current/textsearch-controls.html), [trigram index support](https://www.postgresql.org/docs/current/pgtrgm.html).

Evaluate branch RRF for fallback ordering, and candidate depth as a separate experiment. Fusion alone cannot increase recall when the same entire union reaches the reranker. The existing direct path already distinguishes final count from candidate count; the remaining constraints are branch depth, the tool's 15-row return ceiling, and downstream union contracts. Measure unique relevant lexical additions, identifier recall, fallback nDCG, marginal gain per scoring pair, and database p95. [Original RRF research](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf).

## 5. Audit filtered ANN and scorer behavior under failure

Dense search filters by authorized document IDs before expressing nearest-neighbor ordering. With approximate indexes, pgvector documents that filtering can reduce returned matches and that iterative scans can search further. The actual planner may instead select an exact plan, so this is a benchmark target rather than a confirmed defect. Compare approximate retrieval with exact filtered neighbors across scope sizes. Test bounded scan effort, iterative scans, and exact search for small scopes. Preserve authorization predicates. Measure recall, returned/requested ratio, buffers, and latency. [Dense query](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/documents/services/chunk_search_candidates.py#L198), [pgvector filtering](https://github.com/pgvector/pgvector#filtering).

The adaptive legacy scorer also depends on cached endpoint capability. When optional RAG caching is disabled, that capability cannot be obtained through this path, and selection uses rank fallback. Decouple verified scorer capability from optional result caching. Endpoint discovery can make several calls with per-call timeouts; unify it under an aggregate deadline instead of treating a three-second HTTP timeout as a three-second stage limit. [Capability dependency](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/documents/services/chunk_rerank_selection_provider.py#L210), [cache default](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/aquillm/settings.py#L39).

The older rank-result cache omits model revision, endpoint, source content, and preparation policy from its key; the newer scored cache already has stronger identities. Configuration drift could therefore reuse a stale ranking when workers share a cache, within the default 45-second TTL. Normal rechunking replaces rows with new identities, so ordinary content-edit staleness was not established. Consolidate cache identities and keep whole-pool score fallback rather than mixing incomparable scales. [Old key](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/documents/services/rag_cache.py#L271), [scored identities](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/documents/services/chunk_rerank_score_cache.py#L18).

## 6. Complete conversational query resolution

`RAG_QUERY_REWRITE_ENABLED` calls a placeholder returning the original text. Legacy pronoun handling prepends the first title from the last retrieved-document list. Multi-query preparation splits on question marks, semicolons, and newlines; it is not semantic decomposition. These can misresolve references or miss clauses in a single sentence. [Query construction](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/chat/services/rag_query.py#L65).

Evaluate a bounded contextual rewrite that preserves the original query, exact identifiers, negation, dates, units, and constraints. Use the existing source-continuity path for explicit source references and plural follow-ups. Add semantic subqueries only where the question needs them, keeping a shared cost/deadline budget. Test ordinal citations, multiple papers, topic switches, and constraints inherited from earlier turns. QReCC provides evidence for evaluating rewriting, retrieval, and answering separately; it does not establish that rewriting every AquiLLM question will help. [QReCC](https://aclanthology.org/2021.naacl-main.44/).

## 7. Improve graph contribution through focused ablations

The graph path already overlaps direct retrieval with baseline work, batches extended seed lookup, and enforces bounded workers and exact scope/version checks. Preserve those properties. First compare baseline, direct-only, extended-only, and combined at the same reranker and evidence budgets. Measure graph-only relevant additions, final-evidence survival, complete supporting-set recall, timeout rates, and added latency. A successful duplicate-only branch is different from a failed branch.

Then test three narrower changes:

- Context-weight direct seeds and extended entity seeds. Extended passage mass is currently shared among its associated entities; identity matching alone does not capture the requested relationship.
- Improve passage mapping. Relation evidence inherits maximum endpoint PPR times confidence; repeated contributions retain the maximum. Compare query-aware edge weighting or capped independent contributions, plus a separate ablation of the three-chunks-per-document branch cap.
- Profile gateway serialization, resolver SQL calls, cache misses, and repeated snapshot digests before enlarging budgets. Four gateway families do not imply four complete database hydrations: an adapter cache already shares assembled snapshots. Investigate scoped in-flight request coalescing or consolidated responses only if measured overhead warrants it.

Code: [extended seeds](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/knowledge_graph/retrieval/production_extended.py#L49), [passage mapping](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/knowledge_graph/retrieval/production_runtime_support.py#L71), [topology cache](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/knowledge_graph/projection/topology_adapter.py#L181). HippoRAG 2 motivates query-to-triple grounding and passage-aware graph experiments; its additional model calls should not be assumed to fit AquiLLM's deadlines. [HippoRAG 2](https://arxiv.org/html/2502.14802v1).

Adaptive restart should beat a tuned fixed baseline on held-out labels. Compare fixed 0.15/0.20/0.35/0.50 before testing the heuristic policy, and examine eight-iteration versus converged results offline. The older runbook records 32.36 ms added p95 in a small synthetic local test against a 5 ms target; this is historical evidence, not today's service latency. A later note says development uses adaptive PPR, so reconcile the deployment and evaluation records. [Recorded experiment](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/docs/documents/operations/adaptive-ppr-restart.md#L20), [later deployment note](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/docs/operations/graph-retrieval-latency.md#L71).

## 8. Upgrade scientific source representation in a separate reindex experiment

PDF body extraction joins `pypdf` text without a body page/element map. arXiv concatenates TeX members through a separate route. Fixed character chunks can split paragraphs, tables, equations, and qualifiers. Figure extraction already exists, but crop geometry and whether embeddings used pixels or only fallback captions are not consistently retained. [PDF extraction](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/lib/parsers/documents/pdf.py#L10), [arXiv extraction](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/ingestion/services/arxiv_ingest.py#L68).

Create one versioned extraction representation across upload/arXiv: ordered elements, headings, tables/cells, equations, captions, pages, and regions, with a canonical text-offset mapping. Compare paragraph/token-bounded chunks and title/section embedding prefixes against existing chunks while holding parser and embedding model constant. Keep embedding context separate from citable source text. Then compare parsers separately. Docling's document model and hybrid chunking provide concrete implementation references. [Document model](https://docling-project.github.io/docling/concepts/docling_document/), [chunking](https://docling-project.github.io/docling/concepts/chunking/).

Measure numeric/sign fidelity, table-header association, reading order, support recall, redundant tokens, ingestion cost, and source-region accuracy. Preserve original files. Late chunking and ColPali-style page retrieval are later experiments: they require model/scoring support and are not drop-in replacements for the current pooled 1024-dimensional vector index. [Late chunking](https://arxiv.org/abs/2409.04701), [ColPali](https://arxiv.org/abs/2407.01449).

## 9. Separate evidence sufficiency from ranking and citation syntax

Min-max normalization deliberately expresses within-pool ordering: even an irrelevant pool has a best item. Do not use its maximum as confidence. Existing bounded coverage assessment and iterative acquisition can be evaluated for insufficient evidence; the missing claim is demonstrated answerability calibration, not the absence of a planner. [Normalization](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/chat/services/rag_selection_policy.py#L48), [existing acquisition](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/apps/chat/services/rag_acquisition.py#L31).

Citation validation explicitly checks presence rather than entailment. Extend offline review with sentence-to-source support, qualification preservation, and numeric consistency; start with sampled evaluation before adding an online verifier to every answer. Use held-out unanswerable and contradictory-source cases to choose abstention behavior. [Citation check](https://github.com/AquiLLM/AquiLLM/blob/75efe98c918072649e690979ffdf7211b6d4c455/aquillm/lib/llm/providers/rag_citations.py#L101).

## Recommended execution order

| Order | Deliverable | Evidence required before adoption |
|---|---|---|
| First | Effective configuration/model snapshot, representative labels, stage-level evidence-survival metrics | Reproducible baseline with cold/warm conditions and fixed source revisions. |
| Next | Document embedding identity and scorer capability/deadline consistency | No incompatible vectors or stale scores under outage/configuration tests; bounded failure behavior. |
| Next | Existing windowed/source-preserving mode evaluation | Better complete-support delivery without unacceptable latency or authorization/citation regressions. |
| Then | Lexical ranking, ANN tuning, contextual query resolution | Gains on the relevant held-out slices at a recorded cost; change one component at a time. |
| Then | Graph seed/mapping/overhead experiments and scientific parsing/chunking | Incremental gains over the improved baseline, with reindex and serving cost included. |

Source defaults are not deployment facts: direct RAG defaults off in Python but on in Compose; selection defaults legacy; preservation defaults legacy/off; RAG cache defaults off in settings but on in the example environment. The operational note describes 12 final passages and about 7,000 evidence tokens with adaptive selection/PPR and preservation disabled. No live environment was inspected during this audit.
